# Tron deployment snapshots

[v1.4/deployments.json](v1.4/deployments.json) packages Tron B2BSplitter v1.4
records using the shared
[payment deployment schema](../../../src/reference/payment-deployments.schema.json)
(`ecosystem: "tron"`, `$defs/tronDeployment`).

These records are curated package data. They are not regenerated by
`npm run registry:build`, and no SDK lookup API or payment route is added for Tron.

## Field mapping

Each record links a timestamped upstream artifact (`sourceArtifact`) at the
commit in `source`. Compared with the upstream deployment JSON:

- Splitter role and contract addresses (`splitter`, `tokenList`, `profiles`,
  `admin`, `signer`, `pauser`, `treasury`) are grouped under `contracts`, as in
  EVM records. Addresses stay in Tron base58 form.
- `splitter.stablecoins` maps to `assets`.
- `splitter.deployTx` maps to `transactions.deploy.txHash`.
- `environment` is normalized to `prod`/`dev` and `testnet` is explicit.
- Upstream `status` and `disabledReason` labels are omitted.
- Settlement flags, route IDs and route economics (`routes`) are preserved as
  upstream recorded them. They are not independently verified.

`abi` points to the packaged Hardhat artifact under
[`registry/abi/tron/`](../../abi/tron/). Its layout is
`<Contract>/<Contract>.json`, the same as the EVM ABI bundles.

## Refreshing

1. In the upstream contract repository, compare `deployments/*-latest.json` with
   the matching timestamped file, and pin the commit that contains it.
2. Map the fields as described above. Keep each network's own capture time in
   `timestamp`.
3. Copy the ABI from that commit's build output into
   `registry/abi/tron/<Contract>/<Contract>.json`. Do not ship Hardhat
   `.dbg.json` files, because they reference `build-info` files that are not
   packaged.
4. Validate against the shared schema, run `npm test`, then bump the package
   version and add a root changelog entry.

## Evidence boundary

These are historical inputs, not live verification or payment authorization.
Before relying on a route, verify the deployed code, roles and pause state,
backend capabilities, the merchant quote, and the executor's runtime checks.
