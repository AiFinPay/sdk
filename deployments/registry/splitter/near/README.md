# NEAR deployment snapshots

[deployments.json](deployments.json) packages mainnet and testnet splitter
records using the shared
[payment deployment schema](../../../src/reference/payment-deployments.schema.json).
It also preserves the upstream council membership input with a separate
provenance link; membership does not establish DAO policy or approval thresholds.

The curated-snapshot approach follows the Aptos registry: no new fetcher,
programmatic lookup API, or SDK payment route is introduced. These records are
not regenerated by `npm run registry:build`.

Each record links a timestamped upstream artifact at the commit in `source`.
`wasmCodeHash` maps the upstream `runtimeCodeHash`, environments use `prod`/`dev`,
and upstream `status` labels are omitted. Settlement flags, transaction evidence,
roles, route economics, and captured splitter state are otherwise preserved.
No WASM binary or ABI is bundled; `sourceArtifact` links the deployment JSON,
not a downloadable executable.

To refresh, compare upstream `deployments/*-latest.json` with the corresponding
timestamped files, pin the commit containing those files, and preserve per-network
capture times. Compare council membership against its own source artifact rather
than inferring policy from member count. Validate the records against the shared
schema and update the package version and root changelog.

These are historical inputs, not live verification or payment authorization.
Before relying on a route, verify deployed code, contract access keys, DAO policy,
roles and pause state, backend capabilities, the merchant quote, and executor
runtime checks. DAO role assignments alone do not prove exclusive upgrade
control. Consult the upstream deployment guide at the recorded source commit for
its access-key and DAO-policy caveats.
