# @aifinpay/deployments — agent guide

Canonical deployment registry grabber. Fetches the latest AIFP deployment records from upstream contract repositories and produces versioned registry files with governance metadata.

## Scope

- This package only (`src/`, `tests/`, `registry/`, `package.json`). Do not touch `node/`, `python/`, `mcp/`, `mcp-http/`, `wallet/`, `gate/`, `skill/`.
- Entry: `src/index.ts`. Core: `src/grabber.ts` (EVM + Solana fetch + latest-per-chain logic + split-file writer), `src/types.ts` (registry types), `src/build.ts` (CLI that writes split files).
- `src/reference/payment-deployments.schema.json` defines the schema linked by the versioned registry JSON files.
- Output artifacts live in `registry/`:
  - `registry/splitter/` — versioned registry with governance metadata:
    - `evm/v1.4/deployments.json` — EVM v1.4 full contract suite with governance Safe info
    - `evm/v1.3/deployments.json` — EVM v1.3 route table (merchant-aifp1 + agent-x402)
    - `evm/v1.2/deployments.json` — EVM v1.2 legacy with `paymentId` replay guard
    - `evm/v1.1/deployments.json` — EVM v1.1 initial production release
    - `solana/deployments.json` — Solana v1.4 program deployments
    - `casper/deployments.json` — Casper deployment records
    - `aptos/` — Aptos mainnet/testnet payment and multisig snapshots
    - `near/` — curated NEAR mainnet/testnet account/WASM and council snapshots
    - `INDEX.md` — registry links and verification checklist
  - `registry/abi/` — Aptos and EVM ABI bundles plus Tron ABI artifacts.
  - `registry/idl/` — Solana IDL copies (`solana/splitter-v14/`) plus Aptos/Casper IDL artifacts.
- The [v1.3 route snapshot](registry/splitter/evm/v1.3/deployments.json) is
  not regenerated by the grabber. Maintain its provenance explicitly and review
  downstream impact in the
  [SDK generator](../node/scripts/generate-splitter-routes.mjs) when updating it.

## Evidence, not snapshots

- Resolve addresses, program IDs, runtime hashes, provenance, governance and
  settlement fields from the actual JSON linked in the
  [registry index](registry/splitter/INDEX.md), not copied Markdown tables.
- Settlement flags are packaged metadata, not currently verified backend/runtime
  findings. Require fresh chain evidence and actual backend
  receipt-verification/end-to-end evidence before claiming availability.
- Follow the index's links to SDK resolution and settlement checks. Preserve
  fail-closed gates; no documentation update authorizes activation or bypass.

## Commands

- `npm run build` — `tsc -p tsconfig.json`
- `npm run registry:build` — `node dist/build.js`, fetches upstream and writes `registry/splitter/evm/v1.4/deployments.json` + `registry/splitter/solana/deployments.json`
- `npm test` — `vitest run` (from `deployments/`)

## Rules

- Keep `IDL_DIR` and ABI paths under `registry/` so they ship with the package (`files: ["dist", "registry"]`).
- Consult [registry types](src/types.ts) and the selected JSON for field layout;
  do not assume all ecosystems or historical versions have identical records.
- Tests are offline-only and must not write files to `registry/` or `src/`. Use `tests/tmp/` for temporary test output (gitignored).
- Solana IDL files live in `registry/idl/solana/splitter-v14/` — do not regenerate them, they are maintained manually.
- Aptos snapshots in `registry/splitter/aptos/` are curated and are not regenerated by `registry:build`; keep referenced ABI files in `registry/abi/aptos/`.
- NEAR snapshots in `registry/splitter/near/` are curated and are not regenerated by `registry:build`; preserve immutable upstream artifact links and do not infer DAO policy from council membership.
- Bump `version` + `CHANGELOG.md` together when changing shipped files; CI checks via `scripts/check-version-bump.mjs`.
